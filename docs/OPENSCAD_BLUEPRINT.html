Architecture blueprint · rev A · 2026-08-23

OpenSCAD From Scratch

A clean-room reimplementation of the OpenSCAD language in pure Rust — WASM + WebGL2 in the browser, served from a self-contained localhost binary, with MCP tools so an AI companion can design alongside you.

lang Rust, zero third-party crates targets wasm32 + native license posture proprietary-safe repo endlessa/unbroken-ahk

The verdict

This is viable, and it is legally clean. The OpenSCAD language is an uncopyrightable functional interface; a clean-room implementation built from the CC-BY-SA manual and black-box observation of the official binary carries zero GPL obligations. You can keep every line proprietary.

The language is the tractable 15%. The geometry kernel is the project. A full lexer/parser/evaluator with OpenSCAD's genuinely strange semantics is weeks of careful work. Robust 3D booleans on degenerate-by-design CAD input is months, and it is where reimplementations die. The plan below sequences the work so a useful, interactive tool ships in ~2–3 months while the hard kernel lands incrementally behind it.

One shared core, two frontends. Every crate that computes stays OS-free and compiles identically to wasm32 (browser) and native (HTTP server, MCP, CLI). The AI never touches WASM; the browser never touches the filesystem. A differential-test harness that runs the real OpenSCAD binary as an oracle is the backbone from week one.

Part 01

Licensing: a clear yes, with discipline

The GPL binds code that copies or derives from GPL code — never behavioral compatibility. OpenSCAD the application is GPL-2.0-or-later and its CGAL kernel is GPL, but its language — grammar, keywords, builtin names, semantics, the .scad format — is a functional system, not protectable expression.

The controlling authority is SAS Institute v. World Programming (CJEU C-406/10): a company clean-roomed the entire SAS language from manuals and black-box observation and won. The parallel US case ended with SAS losing too. Google v. Oracle left a sliver of US API-copyright uncertainty, but OpenSCAD's few dozen short builtin names are far weaker ground than Oracle's 11,500 lines of declarations. Wine, Mono, and every "X-compatible" interpreter rest on the same footing.

One accuracy note worth internalizing: in the US action, World Programming actually lost contract claims (~$79M) because SAS's license forbade reverse engineering. Black-box probing is safe here specifically because GPLv2 §0 says running the program is unrestricted — the method is protected by OpenSCAD's own license terms, not by some general immunity.

Safe to use

  • OpenSCAD User Manual on Wikibooks (CC-BY-SA) — read freely; paraphrase, never paste prose into your docs or strings
  • openscad.org cheat sheet — unprotectable functional facts; use as the completeness checklist
  • Running the official binary on your own probe files and recording outputs as golden references — the primary semantics oracle
  • Geometry papers & textbooks: Shewchuk predicates, Goldfeather/SCS, Vatti clipping, quickhull, Bernstein–Fussell
  • Permissive reference code if you choose: Manifold (Apache-2.0), Clipper (Boost/BSL), earcut (ISC), csg.js (MIT)
  • Format specs: STL, OFF, 3MF, DXF, SVG, TrueType, RFC 1951, RFC 6455
  • Liberation fonts from upstream Red Hat (SIL OFL) — bundleable in closed source

Hard bans

  • Never open the OpenSCAD source tree — parser.y, lexer.l, evaluator, headers. Reading destroys the clean-room evidentiary posture
  • Never copy their regression tests or examples — the #1 realistic contamination vector; author every test .scad in-house
  • Never read CGAL or OpenCSG source (both GPL) — implement image-space CSG from the papers, not the library
  • Don't vendor MCAD (LGPL) — let users fetch libraries themselves
  • Don't ship the official binary in public artifacts (private CI use is fine)
  • No "OpenSCAD" in your product name, no logo derivatives — unregistered trademark/passing-off risk is real. Distinct name + "compatible with the OpenSCAD language; not affiliated" is the pattern
  • Watch AI-assistant regurgitation — the GPL evaluator is in training corpora; review suspiciously C++-shaped Rust

Process that makes it stick

  • Sources policy, committed to the repo: one page listing permitted and forbidden references, before serious coding starts.
  • Provenance log: every behavioral question answered by probing gets its probe file and the oracle's output recorded. This is the evidence that wins a hypothetical dispute — and it doubles as your test suite.
  • License posture: fully proprietary is available. If you ever open parts, use MIT OR Apache-2.0 (patent grant, no disclosure). A sensible split: keep the engine private, open the thin MCP/HTTP scaffolding for adoption.
  • The one flagged exception: the Manifold library (the robust-boolean kernel modern OpenSCAD itself adopted) is Apache-2.0 — legally portable to Rust with attribution only, no disclosure. Your all-our-own-code rule is stricter than the legal requirement here; since the boolean kernel is the single hardest subsystem, keep this option consciously on the table rather than off it by default. Implementing from the papers alone is also fine — just slower.

Shape of the system

One Cargo workspace. Core crates are pure computation — no filesystem, no clock, no threads, no #[cfg] — so they compile bit-for-bit to both targets and are debugged natively with ordinary cargo test.

The frontends inject a platform trait (file provider, clock, entropy, log). The evaluator resolves include/use/import() through a virtual filesystem: native roots it at the project directory (path-canonicalized, symlink-escape-checked — in the MCP process too, not just the browser), wasm backs it with an in-memory map fed over the server's file API. That one seam gives the MCP server dirty-buffer-aware includes for free and makes the browser and AI see identical worlds.

The serve process owns the session: document buffers with monotonic revisions, customizer values, camera pose. The browser editor syncs over a hand-rolled WebSocket; MCP tools mutate the same store. Human keystrokes and AI edits meet through revision-checked writes — reject-and-rebase on conflict, ~50 lines, no CRDT theater.

Part 03

The language, honestly

Pin the baseline to OpenSCAD 2021.01 semantics, report version_num() = 20210100, and add newer features behind explicit flags. (Verify against a live check whether a post-2021 stable has shipped before freezing this — libraries feature-detect on the version you report.)

"Full language" spans 22 categories: 3D/2D primitives, transforms, booleans, extrusions, hull/minkowski/offset/projection/surface/render, control flow, list comprehensions, modules/functions/children, function literals, ~60 builtins, all $-variables, modifiers * ! # %, include/use, import/export, the comment-based customizer, and echo/assert formatting. None of it is individually hard. What kills compatibility is the semantics no one expects:

  • Assignment is not imperative. Last textual assignment per scope wins, taking effect at the first assignment's position: a=1; b=a; a=2; yields b==2. Blocks can't mutate outer variables.
  • All $-variables are dynamically scoped through the call stack, and children() sees the caller's lexical scope with the instantiating site's $-environment. Get this wrong and BOSL2 breaks.
  • undef propagates with warnings, never errors. [1,2]+1 is undef; vector*vector is a dot product; there is no elementwise multiply and no string +.
  • The ternary is the only lazy construct — an eager ternary infinite-loops every recursive library. Tail-call elimination is required (~1M-frame tail recursion must work); on wasm the evaluator needs an explicit heap stack, not the shadow stack.
  • Tessellation is contractual. Fragment formula $fn ? max($fn,3) : ceil(max(min(360/$fa, 2πr/$fs), 5)); circles are inscribed with vertex 0 at +X; spheres stack ceil(frags/2) rings at half-step offsets with no pole vertices. Users build hex nuts out of these exact choices.
  • polyhedron faces wind clockwise from outside — the reverse of STL convention. echo/str() format floats %g-style at 6 significant digits (0.1+0.2 prints 0.3) — golden tests must reuse the exact formatter. search() returns ragged mixed shapes that libraries pattern-match; clone it bug-for-bug.
  • Preview ≠ render: % objects show in preview but vanish from export, # the opposite emphasis, $preview flips, convexity only matters to the preview renderer (parse it everywhere, may ignore it). The warning set itself is compatibility surface — serious users run --hardwarnings in CI.
  • Geometry caching is compatibility. A for-loop stamping one module 1000× only finishes because identical subtrees hit a cache. Budget a subtree-keyed geometry cache early, not as an optimization.
Design consequence: the parser must be error-tolerant (recover and continue, multiple diagnostics per pass) from the start — the editor squiggles and the MCP scad_check tool both depend on it, and retrofitting recovery into a halt-on-first-error parser is miserable.
Part 04

Geometry kernel: the make-or-break, phased

OpenSCAD input is degenerate by construction — mirrored halves, rotated copies, flush faces are the idiom, not the edge case. Strategy: buy time with an image-space preview, build the bulletproof 2D kernel that half the language sits on, then land robust 3D booleans with a declared fallback.

The 2D kernel is the quiet workhorse

square/circle/polygon/text/offset/projection/extrude-caps all sit on 2D booleans. Implement Vatti/Clipper-style scanline clipping with integer coordinate snapping (scale by ~1e7, exact i64/i128 intersection math, unscale at the end) — that single decision buys total robustness in 2D. Ear-clipping triangulation with holes, Clipper-style offsetting (round joins consume $fn/$fa/$fs), monotone-chain hull. This is 6–9 weeks and an order of magnitude easier than 3D; it unblocks half the language and both extrusions.

Everything else, difficulty-ranked

  • Easy: primitive tessellation to the exact fragment formula (days — lock with canonicalized-mesh comparison against the oracle, never byte-diffed STL); rotate_extrude; 2D hull; point-in-mesh; BVH.
  • Medium: linear_extrude with twist/scale (non-planar side quads need consistent shorter-diagonal splits; scale→0 collapses to a welded apex); quickhull 3D hardened for coplanar input; projection(cut) by exact z=0 slicing; mesh repair/validation (welding, orientation, 2-manifold check — also your honesty layer for the stopgap kernel).
  • Hard: text() — TrueType parsing is mechanical but large (see Part 05); projection(cut=false) as a batched union tree over projected triangles.
  • Brutal, scope deliberately: nonconvex minkowski (convex path = hull of pairwise vertex sums, days; general path = convex decomposition + giant union — upstream is notoriously slow here too, parity means "similarly slow"); roof() is experimental upstream — skip and document.
Part 05

WASM, WebGL & the server

wasm32 without wasm-bindgen

Entirely practical — wasm-bindgen automates this boundary; it doesn't enable it. crate-type = ["cdylib"], #[no_mangle] extern "C" exports, and one ABI rule: only scalars and (ptr, len) pairs cross the boundary — never structs by value. Export wasm_alloc/wasm_free; strings go in via TextEncoder → alloc → memory write; results come back as one #[repr(C)] header struct JS reads with a little-endian DataView.

  • The #1 glue bug: typed-array views detach when linear memory grows. Never cache a view across any call that can allocate — recreate immediately before use.
  • Silent std landmines on this target: Instant::now() panics at runtime; println! goes nowhere; no threads. Route time/log/entropy through ~4 imported host functions. panic = "abort" plus a panic hook that ships the message to console.error before the trap; treat any trap as fatal and re-instantiate (keep the compiled Module cached — milliseconds).
  • Run the engine in a Web Worker from day one. A 30-second render must never freeze the UI, and Worker.terminate() is your only preemption — that plus a cooperative cancel flag is the interrupt story. Don't plan on SharedArrayBuffer threads; later parallelism is N independent instances in N workers.
  • Determinism discipline: HashMap iteration order differs native-vs-wasm — anywhere order can reach output geometry, use BTreeMap/sorted iteration or golden tests rot.

Rust computes, JS renders

WASM has no GPU access, so something crosses to JS regardless — choose the coarse boundary. Rust hands over finished f32 vertex/normal buffers, u32 triangle and edge indices, and a small draw-list (offsets, RGBA, modifier flags). Hand-written JS (~600–900 lines, no npm, no bundler) owns WebGL2: a 120-line mat4/vec3 library, Blinn-Phong with headlight, orbit/pan/zoom camera honoring $vpr/$vpt/$vpd, edge overlay with polygonOffset, adaptive grid. The alternative — extern-importing the GL API into Rust — is hundreds of stateful shim functions with handle tables; reject it. This boundary also makes a future WebGPU backend a contained swap, and the stencil buffer WebGL2 gives you is exactly what the Goldfeather preview needs. Handle webglcontextlost/restored — long-lived tabs will hit it.

The localhost server: the easiest component

TcpListener on 127.0.0.1 only, thread-per-connection, hand-rolled HTTP/1.1 (~300–500 lines: header caps, Content-Length bodies, keep-alive, HEAD). Every asset — HTML, JS, the .wasm blob, the default font — embedded via include_bytes! so the binary is fully self-contained; serve .wasm as application/wasm or streaming instantiation fails. SSE for live-reload and progress push (~30 lines + browser-native reconnection); add the RFC 6455 WebSocket (~250–350 lines; needs your own SHA-1 + base64) when editor sync arrives. Localhost binding is necessary but not sufficient:

  • Validate Host against {localhost, 127.0.0.1, [::1]}:port — kills DNS rebinding outright.
  • Send no Access-Control-Allow-Origin at all; validate Origin on POSTs and on WebSocket upgrades (upgrades bypass CORS entirely).
  • Require a custom header with a per-launch random token on state-changing endpoints — cross-origin pages can send blind POSTs but can't set custom headers.

text() and the file formats

A minimal-correct TrueType engine is ~1,200–2,000 lines against excellent public specs: cmap formats 4/12, glyf quadratic outlines including composites (every accented Latin glyph is one — not optional) and the implied on-curve midpoint trap, hmtx/hhea metrics, TTC headers (macOS ships .ttc), kern now and a GPOS PairPos subset in v2. Flatten quadratics with $fn-derived tolerance, resolve contour overlap with the 2D winding union you already have. Declare loudly: no CFF/.otf initially, no HarfBuzz-class shaping — Latin with kerning first, registered font files + an embedded OFL Liberation face, and per-codepoint fallback documented as a divergence. Fonts are attacker-shaped input: bounds-check everything, cap composite recursion, fuzz natively.

Editor without CodeMirror

v0 is a plain textarea + error list + Ctrl-Enter render — ships in a day. v1 stacks a transparent-text textarea over a <pre> backdrop colored by the same wasm lexer the compiler uses (export tokenize() → one source of truth for highlighting). Squiggles via text-decoration: underline wavy on diagnostic spans; convert Rust's UTF-8 byte offsets to UTF-16 columns on the Rust side. Skip contenteditable entirely. Known cost: programmatic edits (tab insertion, AI edits pushed into the buffer) break native textarea undo — plan to own undo/redo once scad_edit lands, which the revision history conveniently already supports.

Part 06

MCP: the AI design companion

One transport-agnostic JSON-RPC dispatcher, exposed two ways: POST /mcp on the same localhost server (primary — zero-IPC access to the live editor session) and a thin stdio mode that bridges to the running instance (Claude Desktop is stdio-only; stdio is also the conformance-test harness). The MCP server links the core crates natively — no WASM in the AI loop, real debuggability, and a headless CPU rasterizer (~400–700 lines) instead of driving a browser.

Protocol surface is small: pin revision 2025-06-18, negotiate down; implement initialize, ping, tools/list, tools/call; declare tools only. The one rule that makes or breaks the loop: domain failures (syntax errors, timeouts, non-manifold export) are successful responses with isError:true and diagnostics in content — the model reads them and self-corrects. JSON-RPC error objects are for protocol failures only. Every evaluating tool runs under budgets (step counter, wall clock, triangle cap, recursion depth) that name the limit and the source location when tripped — AI-authored .scad will contain $fn=10000 and runaway recursion. Pin and document $preview per tool.

ToolJob

The loop the tool set is shaped for — state it in serverInfo.instructions: read → edit (returns diagnostics) → render → stats/measure to verify numerically → export with manifold gate. readOnlyHint annotations keep the read-side prompt-free in Claude Code, and a checked-in project .mcp.json pointing at http://127.0.0.1:PORT/mcp makes the whole thing auto-discover.

Part 07

What zero-dependency actually costs

The rule is fully workable — this repo's test platform already proves the house style — but it silently adds a second project: infrastructure that has nothing to do with CAD. Budget it explicitly (~2–3 months spread across phases) or the geometry schedule absorbs it invisibly.

Part 08

Testing is the backbone, not a phase

  • Differential oracle from week one. CI runs the official OpenSCAD AppImage headlessly on your own probe files (running GPL software is unrestricted; their test files never enter your tree). Compare echo/warning text verbatim, CSG dumps, and mesh-level equivalence.
  • Canonicalize before comparing meshes: sorted vertex/triangle sets under tolerance — never byte-diffed STL. OpenSCAD doesn't guarantee triangle order across its own versions; promise mesh equivalence and self-consistency instead.
  • Golden native CLI: scad-cli check|render|export|stats makes every pipeline stage scriptable — hashed deterministic renders, blessed fixtures, and the same binary the MCP server uses.
  • Fuzz the parsers (fonts, DXF, SVG, JSON, inflate) natively with a 50-line PRNG loop; fuzz the boolean kernel with generated coincident-geometry adversaries — mirrored, rotated, grid-aligned.
  • Provenance log doubles as the compat spec: every quirk pinned by a probe file + recorded oracle output is simultaneously legal evidence and a regression test.
  • Acceptance corpus, license-checked: BOSL2 (BSD-2, shippable) as the semantic stress test; GPL libraries run privately in CI only, never vendored.
Part 09

Roadmap

Solo, experienced, aggressively AI-assisted. AI assist genuinely compresses the well-specified parts — format parsers, published algorithms, test generation — and deliberately does not shrink the robust-kernel degeneracy tail.

Phase 0months 0–2.5

A real tool with no booleans

Full lexer/parser/evaluator with the honest semantics of Part 03 · exact primitive tessellation · WebGL2 viewer with camera + edges · HTTP server with embedded assets · MCP server with check/eval/docs/read/edit (none of these need geometry) · differential harness running the oracle. Ships: a live .scad previewer with an AI copilot for language-level work.

Phase 1months 1.5–5, overlapping

Interactive parity + the 2D kernel

Goldfeather stencil preview (F5-equivalent booleans with zero kernel) · integer-snapped 2D booleans, triangulation, offset · linear/rotate_extrude · quickhull + convex minkowski · customizer panel. Ships: most real-world scripts preview interactively.

Phase 2≤1 month, optional

Stopgap export, honestly labeled

csg.js-style BSP + vertex welding + a manifold validator that reports when output is broken. Time-boxed hard; every hour hardening it is stolen from Phase 3. Skip if export urgency is low.

Phase 3months 4–12

The real kernel

Shewchuk predicates → BVH → exact arrangement → winding classification → manifold output, fuzzed continuously against the oracle. Decision gate at month ~6: if the degeneracy tail is eating the schedule, pivot F6 to Bernstein–Fussell exact BSP (provably robust, slower) and keep this as the performance track.

Phase 4months 6–14, parallel

The long tail

text() Latin subset · projection · surface + PNG decode · import/export formats · nonconvex minkowski with documented caveats · scad_measure/render_diff · animation runner ($t) · worker-pool parallelism if profiling demands it.
